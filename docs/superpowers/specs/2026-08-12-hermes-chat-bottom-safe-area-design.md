# Hermes 聊天底部安全区设计

日期：2026-08-12  
状态：用户已确认方案一，待书面规格复核  
目标设备：ZecTrix Note4，400 × 300，1bpp 黑白墨水屏

## 1. 目标

修复 Hermes 聊天记录的最后一个气泡与屏幕底部操作提示重叠的问题。聊天内容必须限制在独立的可见区域中，任何气泡文字、边框或留白都不得进入底部操作栏。

当用户语音文字或 Hermes 新回复加入消息列表时，聊天区自动定位到最新内容。电量、Wi-Fi、时钟等与消息无关的刷新不重建气泡，也不重置聊天滚动位置。

## 2. 非目标

- 不增加上下键翻页、滚动或循环逻辑。
- 不修改上下键调节音量的现有行为。
- 不修改确认键录音、发送、重试、双击返回或长按进入设置的行为。
- 不修改 Hermes 对话历史上限、文字截断上限、字体、气泡宽度或角色对齐方式。
- 不修改后端、Gateway 插件、同步协议、NVS、分区表或 LittleFS/storage。

## 3. 根因

当前 `HermesScene` 把 `chat_area_` 和 `chat_content_` 都设为从状态栏底部一直延伸到屏幕最底部：

```text
y = 24
height = 300 - 24 = 276
bottom = 300
```

但 `hint_label_` 又相对整个根节点定位在底部，其文字位于同一块 `y < 300` 的范围内。因此最后一个气泡被自动滚到底部时，它与操作提示占用了同一组像素。照片中气泡边框和回复文字已进入底部提示行，属于布局边界错误，不是局刷残影或字体问题。

## 4. 方案比较

### 4.1 独立底部安全区（采用）

从聊天视口高度中扣除固定底部操作栏，并让操作栏使用不透明白色背景。聊天容器自身负责裁剪，操作栏背景作为第二层防护。这一方案直接修正几何边界，不依赖文本长度或气泡数量。

### 4.2 白色遮罩（不采用）

保留全高聊天区，只用白色矩形盖住底部内容。这会把气泡边框直接截断，并且滚动算法仍认为被遮住的区域可见，只是隐藏症状。

### 4.3 手工挑选末尾消息（不采用）

根据气泡高度只绘制能装入屏幕的最后几条消息。这需要重写消息布局和分页状态，而用户已明确不需要按键翻页，不引入这一复杂度。

## 5. 布局契约

使用与 400 × 300 屏幕一致的固定几何：

```text
0..23      状态栏（24 px）
24..259    聊天视口（236 px）
260..299   底部操作栏安全区（40 px）
```

具体约束：

- `chat_area_` 定位在 `y = theme::kStatusBarHeight`，高度为 `LV_VER_RES - theme::kStatusBarHeight - 40`。
- `chat_content_` 始终与 `chat_area_` 同高，不再使用到屏幕底部的高度。
- 底部操作栏占据 `y = 260..299`，背景为不透明白色，边框为 0。
- `hint_label_` 位于操作栏内部水平、垂直居中，宽度不超过 384 px。
- 气泡容器只在 `chat_area_` 内滚动；不设置 `LV_OBJ_FLAG_OVERFLOW_VISIBLE`。
- 聊天内容继续保留顶部、底部内边距和气泡行间距；最后一个气泡的可见边框与操作栏之间必须至少保留聊天容器的底部内边距。
- 录音、发送、思考和错误状态可以隐藏聊天区或操作提示，但不改变两个区域的几何定义。

## 6. 滚动与更新规则

`RenderMessages` 将“消息是否变化”与“Hermes 状态是否变化”分开：

1. 使用角色、经屏幕清理的文字和消息数量构造消息 key。
2. 只有 key 或消息数量变化时，才清空并重建气泡。
3. 气泡全部创建后，先执行一次 LVGL 布局计算，再把 `chat_content_` 滚到最大纵向滚动位置。
4. 自动定位只发生在消息变化后；状态栏、电量、Wi-Fi、时钟或 Hermes 状态变化不重置滚动位置。
5. 如果消息总高度不超过聊天视口，最大滚动位置为 0，布局保持在顶部。
6. `AppendBubble` 只负责创建和布局单个气泡，不在每条消息后单独滚动，避免重建期间多次请求局刷或产生中间滚动位置。

## 7. 按键和文案

保持当前所有按键契约：

- Hermes 空闲页上键：音量 +1。
- Hermes 空闲页下键：音量 -1。
- 录音期间上下键：继续调节音量。
- 确认键、双击确认和长按确认：保持当前行为。
- 底部提示仍显示“上/下 调音量”，不增加“翻页”文案。

## 8. 组件边界

- `HermesScene` 继续负责场景状态、按键路由和 LVGL 节点生命周期。
- 底部操作栏是 `HermesScene` 的子节点，不抽成全局组件，因为当前只有 Hermes 聊天需要这一结构。
- 可测试的几何常量和“消息变化后自动到最新”判定保持为无 LVGL 副作用的纯 C++ 契约，使 host 端回归测试可在不启动 ESP-IDF 的情况下执行。
- 不改变 `HermesService::Snapshot()` 和消息结构，避免把纯 UI 修复扩散到服务层。

## 9. 失败与边界情况

- 没有消息：保持待机麦克风和“按确认开始说话”界面。
- 只有一条短消息：消息从聊天区顶部开始布局，不强制贴底。
- 消息总高度超过可见区：自动显示最新内容，旧消息被聊天视口裁剪，不进入底部操作栏。
- 单条消息本身高于聊天视口：保持现有 120 字屏幕截断策略，聊天视口显示该气泡末尾，操作栏仍不重叠。
- 与消息无关的 UI 事件：不清空气泡、不改变滚动位置。
- 操作栏节点创建或销毁与其他节点遵守同一 `OnEnter`/`OnExit` 生命周期，不留下悬空指针。

## 10. 验证

### 10.1 Host 端回归测试

- 状态栏高度为 24 px、底部操作栏为 40 px 时，聊天区为 `y=24, height=236, bottom=260`。
- 聊天区底边不大于操作栏顶边，两个区域不相交。
- 消息 key 或数量变化时要求自动定位最新内容。
- 只有 Hermes 状态、电量、Wi-Fi 或时钟变化时，不要求重置滚动位置。
- 回归测试必须先在旧实现上因“聊天区与操作栏重叠”或“缺少消息变化滚动契约”失败，再在修复后通过。

### 10.2 固件构建

- 使用仓库固定的 ESP-IDF 5.5.x 环境完成 `idf.py -C firmware build`。
- 确认不增加分区表、NVS 或同步协议变更。

### 10.3 真机验收

1. 只将新 factory app 写入 `0x10000`，启用写入后回读校验。
2. 不覆盖 bootloader、分区表、NVS、`phy_init` 或 LittleFS/storage。
3. 刷入前保留可回滚的旧 factory 应用备份；不删除现有受保护区备份。
4. 复用真实 Hermes 长对话，使最新气泡高度超过聊天视口。
5. 确认最新用户文字和助手回复可见，最后一个气泡边框与底部操作栏之间有明确空隙。
6. 确认上下键仍调节音量，确认键、双击和长按功能保持不变。
7. 以照片或现场观察记录真机最终布局，不仅依赖构建成功。

## 11. 完成标准

只有同时满足以下条件才可称为完成：

- 底部安全区与聊天视口的几何契约通过 host 端回归测试。
- 新消息到达时自动显示最新内容，非消息刷新不重置滚动位置。
- 底部操作栏使用独立不透明区域，气泡不进入该区域。
- 上下键音量、录音、返回和设置入口的行为没有变化。
- ESP-IDF 5.5.x 完整构建通过。
- 只刷入 factory app，回读与构建产物一致，受保护分区保持不变。
- 真机长对话显示证明最后一个气泡与底部操作栏无重叠。
